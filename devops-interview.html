AWS Interview Q&A

Core AWS questions grouped by domain — services, security, DevOps & containers, and practical scenario how-tos. Perfect for interview prep and quick reference.

☁️ Core AWS Services
Q1 – Q20 Compute · Storage · Network · DB · Serverless · Monitoring

The foundational services every AWS practitioner must know — from compute (EC2, Lambda) and storage (S3, EBS, Glacier) through networking (VPC, Route 53, CloudFront), databases (RDS), and observability (CloudWatch, CloudTrail).

Q1What is AWS?
Amazon Web Services (AWS) is a comprehensive and widely adopted cloud platform offering over 200 fully featured services from data centers globally. It provides infrastructure services such as computing power, storage, and networking on a pay-as-you-go basis.
Q2What are the core cloud service models?
  • IaaS (Infrastructure as a Service): e.g., EC2, EBS — users manage OS and applications.
  • PaaS (Platform as a Service): e.g., Elastic Beanstalk — users focus on deployment without worrying about infrastructure.
  • SaaS (Software as a Service): e.g., Amazon WorkMail — ready-to-use software delivered over the internet.
Q3What is EC2?
Amazon EC2 (Elastic Compute Cloud) provides resizable compute capacity in the cloud. It allows you to run virtual servers, scale them up or down, and pay only for what you use.
Q4What is Amazon S3?
Amazon S3 (Simple Storage Service) is an object storage service offering industry-leading scalability, data availability, and performance. Commonly used for backup, archiving, and serving static content.
Q5What is IAM?
AWS Identity and Access Management (IAM) allows you to manage access to AWS services securely. It lets you create and manage users, groups, and roles, and use permissions to allow or deny access.
Q6What is a VPC?
A Virtual Private Cloud (VPC) is a logically isolated section of AWS where you define your own network configuration, including IP ranges, subnets, route tables, and gateways.
Q7What is Route 53?
Amazon Route 53 is a scalable and highly available Domain Name System (DNS) web service. It routes users to infrastructure both inside and outside AWS.
Q8What is CloudFront?
Amazon CloudFront is a fast content delivery network (CDN) service that securely delivers data, videos, applications, and APIs to customers globally with low latency.
Q9What is Amazon RDS?
Amazon Relational Database Service (RDS) makes it easier to set up, operate, and scale relational databases such as MySQL, PostgreSQL, Oracle, and SQL Server in the cloud.
Q10What is CloudFormation?
AWS CloudFormation provides a common language for modeling and provisioning AWS infrastructure through code. You can use JSON or YAML templates to automate the creation of resources.
Q11What is Auto Scaling?
Auto Scaling helps you maintain application availability and scale EC2 capacity up or down automatically according to conditions you define — such as CPU utilization or request count thresholds.
Q12What is Elastic Load Balancing?
Elastic Load Balancing (ELB) automatically distributes incoming application traffic across multiple targets — EC2 instances, containers, and IP addresses — for fault tolerance and availability.
Q13What is AWS Lambda?
AWS Lambda is a serverless compute service that lets you run code without provisioning or managing servers. You pay only for the compute time you consume — billed in milliseconds.
Q14What is Amazon SNS?
Amazon Simple Notification Service (SNS) is a fully managed pub/sub messaging service that enables you to decouple microservices and fan out messages to multiple subscribers (email, SMS, Lambda, SQS) simultaneously.
Q15What is Amazon SQS?
Amazon Simple Queue Service (SQS) is a fully managed message queuing service that enables decoupling and scaling of microservices and distributed systems. Messages are stored in the queue until a consumer processes and deletes them.
Q16What is AWS CloudTrail?
AWS CloudTrail enables governance, compliance, and auditing by recording all API calls and account activity across your AWS infrastructure — answering who did what, when, and from where.
Q17What is AWS CloudWatch?
Amazon CloudWatch is a monitoring and observability service that collects metrics, logs, and events. It provides dashboards, alarms, and actionable insights to monitor applications and infrastructure.
Q18What is Elastic Beanstalk?
AWS Elastic Beanstalk is an easy-to-use PaaS service for deploying and scaling web applications. You upload your code, and the service automatically handles deployment, capacity provisioning, load balancing, and health monitoring.
Q19What is EBS?
Amazon Elastic Block Store (EBS) provides persistent block storage volumes for use with EC2 instances, suitable for databases, file systems, and other applications that require durable, low-latency storage.
Q20What is Amazon Glacier?
Amazon S3 Glacier is a secure, durable, and low-cost storage service for data archiving and long-term backup. Retrieval times range from minutes (Flexible Retrieval) to hours (Deep Archive), traded off against cost.

🔐 IAM & Security
Q21 – Q30 IAM · KMS · Cognito · Shield · WAF · Inspector

Security on AWS spans identity (IAM roles, policies, MFA), encryption (KMS, Secrets Manager), network protection (Shield, WAF), compliance scanning (Inspector), and the overarching Shared Responsibility Model.

Q21What are IAM roles?
IAM roles allow AWS resources to act on behalf of users or services. Roles have specific permissions and temporary credentials, and can be assumed by trusted entities — such as EC2 instances, Lambda functions, or cross-account users — without requiring long-term access keys.
Q22How do IAM policies work?
IAM policies are JSON documents that define permissions. They specify which actions are allowed or denied on which resources and under what conditions. Policies can be attached to users, groups, or roles:
  • Identity-based policies: Attached to an IAM identity (user, group, role).
  • Resource-based policies: Attached directly to a resource (e.g., S3 bucket policy).
  • Default deny: Everything is denied by default; a policy must explicitly Allow an action.
Q23What is MFA in AWS?
Multi-Factor Authentication (MFA) adds an additional layer of protection on top of a username and password, requiring a device-based authentication code (virtual app like Google Authenticator, hardware token, or SMS). Should be enforced on the root account and all privileged IAM users.
Q24What is AWS KMS?
AWS Key Management Service (KMS) makes it easy to create and manage cryptographic encryption keys and control their use across AWS services. Supports symmetric and asymmetric keys, key rotation, and fine-grained access policies.
Q25What is the Shared Responsibility Model?
A framework defining the division of security responsibilities:
  • AWS is responsible for security of the cloud: Physical hardware, data centers, networking infrastructure, hypervisor, and managed service software.
  • Customer is responsible for security in the cloud: Operating systems, application code, data classification, IAM configurations, network/firewall settings, and encryption choices.
Q26What is AWS Cognito?
Amazon Cognito enables you to add user sign-up, sign-in, and access control to web and mobile apps. Provides user pools (identity directory) and identity pools (federated identities to grant temporary AWS credentials).
Q27What is AWS Shield?
AWS Shield provides managed DDoS (Distributed Denial of Service) protection:
  • Shield Standard: Free, automatic protection against common Layer 3/4 attacks for all AWS customers.
  • Shield Advanced: Paid tier with enhanced detection, real-time visibility, 24/7 DRT support, and cost protection during attacks.
Q28What is AWS WAF?
AWS Web Application Firewall (WAF) protects web applications from common web exploits like SQL injection and cross-site scripting (XSS). Rules can be based on IP addresses, HTTP headers, request body, or URI strings, and can be deployed on CloudFront, ALB, or API Gateway.
Q29What is AWS Inspector?
Amazon Inspector is an automated security assessment service that continuously scans EC2 instances, container images (ECR), and Lambda functions for software vulnerabilities and unintended network exposure, providing prioritized findings with remediation guidance.
Q30What is AWS Secrets Manager?
Secrets Manager helps you securely store, rotate, manage, and retrieve secrets — database credentials, API keys, and passwords. It supports automatic rotation via Lambda functions and fine-grained access control via IAM policies.

🛠️ DevOps & Containers
Q31 – Q40 CI/CD · IaC · ECS · Fargate · Systems Manager

The AWS DevOps toolkit covers CI/CD (CodePipeline, CodeBuild, CodeDeploy), Infrastructure as Code (CloudFormation, OpsWorks), container orchestration (ECS, Fargate), and developer tooling (Cloud9, CodeStar, Systems Manager).

Q31What is AWS CodePipeline?
AWS CodePipeline is a fully managed CI/CD orchestration service for fast and reliable application and infrastructure updates. It chains together source, build, test, and deploy stages — and supports manual approval gates between stages.
Q32What is AWS CodeDeploy?
AWS CodeDeploy automates code deployments to any compute target — EC2 instances, Lambda functions, or on-premises servers. Supports rolling, blue/green, and canary deployment strategies to minimize downtime.
Q33What is AWS CodeBuild?
AWS CodeBuild is a fully managed continuous integration service that compiles source code, runs tests, and produces deployable packages. It scales automatically — no build servers to manage.
Q34What is Infrastructure as Code (IaC)?
IaC is the practice of managing infrastructure (networks, VMs, load balancers, databases) using machine-readable configuration files — rather than manual processes. AWS tools: CloudFormation (AWS-native, JSON/YAML) and Terraform (multi-cloud, HCL). Benefits: version control, repeatability, drift detection.
Q35What is AWS OpsWorks?
AWS OpsWorks is a configuration management service that provides managed instances of Chef and Puppet — tools that automate server configuration, deployment, and management at scale.
Q36What is AWS Systems Manager?
AWS Systems Manager provides visibility and control of your infrastructure. Key capabilities:
  • Run Command: Execute scripts remotely on EC2 instances without SSH.
  • Parameter Store: Secure storage for configuration data and secrets (with KMS encryption).
  • Patch Manager: Automate OS and application patching.
  • Session Manager: Browser-based shell access — no bastion host or open inbound ports needed.
Q37What is Amazon ECS?
Amazon Elastic Container Service (ECS) is a highly scalable container orchestration service that supports Docker containers. You define tasks and services; ECS handles scheduling, scaling, and cluster management.
Q38What is AWS Fargate?
AWS Fargate is a serverless compute engine for containers that works with both ECS and EKS. It eliminates the need to provision and manage servers — you specify CPU and memory requirements, and AWS runs the containers.
Q39What is AWS Cloud9?
AWS Cloud9 is a cloud-based IDE accessible in a web browser, with built-in code completion, a debugger, and a terminal with direct AWS CLI access. No local setup required — ideal for pair programming and consistent dev environments.
Q40What is AWS CodeStar?
AWS CodeStar is a unified project dashboard that makes it easy to develop, build, and deploy applications on AWS quickly. It integrates CodeCommit, CodeBuild, CodeDeploy, and CodePipeline into a single view with project templates and issue tracking.

🎯 Scenario & How-To Questions
Q41 – Q51 Architecture · Operations · Security · Networking

Practical questions that test your ability to apply AWS knowledge to real-world problems — migration, HA design, DR strategy, CI/CD implementation, cost optimization, logging, and VPC setup.

Q41How would you migrate an on-premises app to AWS?
  • Assess: Inventory the app, dependencies, and data using AWS Migration Hub or Application Discovery Service.
  • Choose a strategy (6 Rs): Rehost (lift-and-shift to EC2), Replatform (move to RDS/Beanstalk with minimal changes), or Refactor (re-architect for serverless/containers).
  • Migrate: Use AWS Database Migration Service (DMS) for databases and Application Migration Service for servers.
  • Validate & cut over: Run in parallel, test thoroughly, then switch DNS.
Q42How do you ensure high availability?
  • Deploy resources across multiple Availability Zones.
  • Use Elastic Load Balancing to distribute traffic and detect unhealthy targets.
  • Configure EC2 Auto Scaling to automatically replace failed instances.
  • Use RDS Multi-AZ for automatic synchronous failover.
  • Design a stateless application tier so any instance can serve any request.
Q43How do you secure data at rest in S3?
  • Enable Server-Side Encryption (SSE) — SSE-S3 (AWS-managed keys) or SSE-KMS (customer-managed keys).
  • Apply S3 bucket policies and IAM policies to restrict access to authorized principals only.
  • Enable S3 Block Public Access at the account and bucket level.
  • Enable S3 Versioning to protect against accidental deletion or overwrites.
Q44How do you handle disaster recovery?
Choose a strategy based on RTO / RPO requirements:
  • Backup & Restore: Lowest cost, highest RTO. Back up regularly to S3; restore from snapshots when needed.
  • Pilot Light: Core infrastructure (DB) always running; app servers launched on failover.
  • Warm Standby: Scaled-down but fully functional copy in another region; scale up on failover.
  • Multi-Site Active-Active: Full production stack in multiple regions; fastest RTO/RPO, highest cost.
Q45How do you monitor AWS resources?
  • CloudWatch: Collect metrics (CPU, memory, custom), set alarms, create dashboards, stream logs via CloudWatch Logs.
  • CloudTrail: Audit all API calls — who changed what, when, and from where.
  • AWS Config: Track resource configuration changes and evaluate compliance rules over time.
  • AWS Health Dashboard: Monitor service events that may affect your account.
Q46How do you optimize costs in AWS?
  • Right-size instances: Use CloudWatch metrics and AWS Compute Optimizer to match instance type to actual usage.
  • Reserved Instances / Savings Plans: Commit to 1–3 year usage for up to 72% discount vs on-demand.
  • Spot Instances: Use for fault-tolerant, interruptible workloads at up to 90% discount.
  • S3 Lifecycle Policies: Auto-transition objects to cheaper storage tiers.
  • Cost Explorer + Billing Alerts: Track spending trends and set budget alarms before costs spike.
Q47How do you implement CI/CD in AWS?
  • Source: Store code in CodeCommit (or GitHub).
  • Build & Test: CodeBuild compiles and runs tests on each commit.
  • Deploy: CodeDeploy pushes the artifact to EC2, Lambda, or ECS.
  • Orchestrate: CodePipeline ties all stages together with optional manual approval gates.
  • Notifications: Use SNS or Slack webhooks to alert the team on failures.
Q48How do you manage secrets?
  • Store secrets in AWS Secrets Manager (supports automatic rotation) or Systems Manager Parameter Store (for config values, optional KMS encryption).
  • Never hardcode credentials in source code or environment variables.
  • Use IAM Roles for EC2, Lambda, and ECS tasks — they receive temporary credentials automatically.
  • Set least-privilege IAM policies controlling who can read each secret.
Q49How do you scale a web app?
  • Compute: EC2 Auto Scaling group with scale-out/in policies (CPU or request count).
  • Traffic: Application Load Balancer distributes requests across all healthy instances.
  • Edge caching: CloudFront caches static assets globally at the CDN edge.
  • App-tier caching: ElastiCache (Redis/Memcached) caches frequent DB queries.
  • Database: RDS Read Replicas offload read traffic; Aurora scales read replicas automatically.
  • Stateless tier: Store sessions in ElastiCache or DynamoDB, not on instance.
Q50How do you implement logging in AWS?
  • CloudTrail: Enable in all regions; send logs to a dedicated S3 bucket for long-term audit retention.
  • CloudWatch Logs: Install the CloudWatch agent on EC2; stream application, OS, and access logs to log groups.
  • VPC Flow Logs: Capture IP traffic metadata for network troubleshooting and security analysis.
  • ALB & S3 access logs: Enable per-service access logging to S3 for request-level audit trails.
  • Alarms & Dashboards: Set metric filters and CloudWatch Alarms on error rate thresholds.
Q51How do you set up a VPC with public and private subnets?
  1. Create a VPC with a CIDR block (e.g., 10.0.0.0/16).
  2. Create public subnets (e.g., 10.0.1.0/24) and private subnets (e.g., 10.0.2.0/24) — across multiple AZs for HA.
  3. Create and attach an Internet Gateway (IGW) to the VPC.
  4. Update the public subnet route table: add route 0.0.0.0/0 → IGW.
  5. Create a NAT Gateway in the public subnet (requires an Elastic IP).
  6. Update the private subnet route table: add route 0.0.0.0/0 → NAT Gateway.
  7. Place public-facing resources (ALB, bastion) in public subnets; place databases and app servers in private subnets.
